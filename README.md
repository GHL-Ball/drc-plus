# 自作 DRC+

Baseball Prospectus の DRC+ を参考にした打撃指標を、R と Stan で算出するコードです。対象は MLB の 2021〜2026 年です。

算出の考え方や、仕様を決めるまでの試行錯誤、検証の結果は、解説記事にまとめています。

- 解説記事：<https://solvingbaseball.com/articles/posts/validation-drc/>

## 方針

- **その年の貢献を推定する。** 本人の過去や翌年の成績は使いません。打者という集団についての情報（打者の分布の形や、イベント間の相関）だけを、複数のシーズンから得ます。
- **打者の効果は部分プーリングで推定する。** 打席数の少ない打者や、打者間の差が小さいイベントほど、平均に強く寄せます。
- **外部要因は、確率を推定する段階で調整する。** 対戦投手、球場、守備、気温などを、得点価値に直す前に調整します。
- **不確実性も推定する。** 事後分布から、標準偏差と 90% 区間を付けます。

## 推定する量

打者 $`i`$ について、次の量を推定します。

```math
\theta_i = \sum_{k} p_{ik}^{\text{中立}} \left( w_k + \delta_{ik} \right)
```

$`k`$ は打席結果のカテゴリ、$`p_{ik}^{\text{中立}}`$ はその打者をリーグの平均的な環境に置いたときに結果 $`k`$ が起きる確率、$`w_k`$ は結果 $`k`$ の得点価値、$`\delta_{ik}`$ は得点価値の補正です。最後に、リーグ平均（野手の打席数で重みづけ）を 100 とする尺度に直します。

```math
\text{自作 DRC+}_i = 100 \times \left(1 + \frac{\theta_i - \theta_{\text{lg}}}{\text{R/PA}}\right)
```

## 算出の流れ

### 1. 逐次的な二項モデル

打席結果を、次の順に 1 つずつ切り出す 8 段階の二項モデルで表します。各段階の確率を掛け合わせると、9 つのカテゴリの確率になり、合計は必ず 1 になります。

| 段階 | 使うデータ | 固定効果 | ランダム効果 | 打者の分布 |
|:--|:--|:--|:--|:--|
| ① 死球 / 全打席 | 結果 | 共通 | 打者、投手 | 正規 |
| ② 四球 / 死球以外の打席 | 結果 | 共通、気温 | 打者、投手、球場 | 正規 |
| ③ 三振 / 四死球以外の打席 | 結果 | 共通、気温 | 打者、投手、球場 | t（自由度 12） |
| ④ 本塁打 / BBE | Statcast | 共通 | 打者、投手 | 正規 |
| ⑤ 失策出塁 / BIP | 結果 | 共通 | 打者、投手、守備側チーム、球場 | 正規 |
| ⑥ アウト / 失策以外の BIP | Statcast | 共通 | 打者、投手 | 正規 |
| ⑦ 単打 / 安打 | Statcast | 共通 | 打者、投手 | 正規 |
| ⑧ 三塁打 / 二塁打・三塁打 | 結果 | 共通 | 打者、投手、守備側チーム、球場 × 打席左右 | 正規 |

「共通」の固定効果は、左打席、プラトーン、野手登板、（2021 年のみ）投手の打席です。モデルの上では、⑥は安打になる確率、⑦は長打になる確率を推定しています。

### 2. Statcast データの利用

④⑥⑦の段階では、打球単位のモデル（GAM）で、各打球が対象のイベントになる確率を出します。その打球を全球場・全条件に置いて確率を平均し（中立化）、0/1 の結果の代わりに目的変数にします。球場・気温・守備は、この打球単位のモデルの側で調整しています。打球の確率は、試合単位の交差検証で、その打球を学習に使っていないモデルから出します。

### 3. 後処理

1. 各段階の事後分布からサンプルを取り出します（400 個）。
2. 四球・三振・本塁打・長打の打者の効果を、6 シーズン共通の相関で縮小し直します。
3. Statcast データを使う段階に、補正係数を掛けます（打球の質だけから出した値は、打者間の差を広く見積もるため）。
4. 中立環境（リーグの実際の打席 3,000 個）で、9 カテゴリの確率を計算します。
5. 得点価値を掛け、得点価値の補正を加え、リーグ平均が 100 になるように調整します。

**得点価値の補正**は、アウト・単打・二塁打が対象です。各打席の得点価値から、同じイベント・同じ塁アウト状況の平均を引いた残差を、打球速度、垂直角度、水平角度、一塁到達タイム、打席の左右で説明するモデル（GAM）を、5 つの塁アウト状況カテゴリごとに作ります。各打球を 5 つのカテゴリに置いてリーグ全体の割合で重み付けし、打者 × イベントごとに平均して縮小したものが $`\delta_{ik}`$ です。

## 構成

| ファイル | 内容 |
|:--|:--|
| `R/00_config.R` | パッケージ、パス、段階とイベントの定義、打球単位のモデル式 |
| `R/01_data.R` | データの読み込み、イベントの分類、シーズン単位のデータ作成 |
| `R/02_fit.R` | 段階ごとの推定 |
| `R/03_post.R` | 後処理（段階間の相関、得点価値の補正、中立環境、得点価値） |
| `stan/stage_binary_v3.stan` | 結果を使う段階のモデル |
| `stan/stage_frac_v1.stan` | Statcast データを使う段階のモデル（中立化した確率を目的変数にする） |
| `scripts/01`〜`03` | 実行の入口（下の「実行順」を参照） |

## 必要なもの

- R 4.5、CmdStan 2.40
- パッケージ：tidyverse、DBI、RSQLite、mgcv、cmdstanr、posterior、here、MASS
- 一球データの SQLite（このリポジトリには含まれません）
- `.Renviron`（`.Renviron.example` を写して、自分の環境のパスを書く）

### データについて

一球データは、[sabRmetrics](https://github.com/saberpowers/sabRmetrics/) で取得した Baseball Savant のデータに、独自に列を加えたものを使っています。そのため、sabRmetrics をそのまま使った場合とは、列名が違ったり、列がなかったりします。下の列を用意したうえで、`R/01_data.R` の読み込み部分を自分のデータに合わせてください。

テーブル名は `pbp`（`R/00_config.R` の `pbp_table` で変えられます）で、2021〜2026 年を 1 つのテーブルに入れ、1 行を 1 球とします。

| 列 | 内容 |
|:--|:--|
| `game_id`、`year`、`at_bat_number` | 試合 ID、シーズン、試合内の打席番号 |
| `half_inning` | イニングが表か裏か（`"top"` / `"bottom"`） |
| `home_team`、`away_team`、`venue_name` | ホームチーム、ビジターチーム、球場名 |
| `batter_id`、`batter_name`、`bat_side` | 打者の MLBAM ID、名前、打席の左右（`"L"` / `"R"`） |
| `pitcher_id`、`pitch_hand` | 投手の MLBAM ID、利き手（`"L"` / `"R"`） |
| `handedness_type` | 打者と投手の左右が同じか（`"Same"` / それ以外） |
| `events` | 打席結果 |
| `outs`、`bases` | 打席開始時のアウト数と走者（一塁・二塁・三塁の順の 3 文字、空いている塁は `"0"`） |
| `launch_speed`、`launch_angle`、`hit_coord_x`、`hit_coord_y` | 打球速度、垂直角度、打球の座標 |
| `temp_f_spin` | 屋内球場は固定値とした試合の気温（華氏） |
| `avg_hp_to_1b` | 打者のその年の一塁到達タイム（Baseball Savant のリーダーボード） |
| `is_last_pitch` | 打席の最後の投球なら 1 |
| `run_value_actual` | その投球での得点価値 |
| `R/PA` | そのシーズンのリーグの R/PA |

## 実行順

上から順に実行する想定です。`02` と `03` は、`01` で読み込んだデータがセッションに残っている前提です。

| スクリプト | 内容 | 所要時間の目安（4 コア） |
|:--|:--|:--|
| `scripts/01_prepare.R` | 関数とデータの読み込み | 数分 |
| `scripts/02_fit.R` | 96 個の推定（6 シーズン × 2 つの版 × 8 段階） | 約 26 時間 |
| `scripts/03_postprocess.R` | 後処理。最終的な表 `drc_final_v3.rds` を作る | 約 2 時間 |

推定と後処理は段階ごと・シーズンごとに保存するので、途中で止めても、再実行すれば続きから始まります。ある段階のモデルだけを変えた場合は、その段階の保存ファイルを消して `02` と `03` を回し直せば済みます。

## 出力

`drc_final_v3.rds`（打者 × シーズン）の主な列です。

| 列 | 内容 |
|:--|:--|
| `plus` | 自作 DRC+（打席数を入れない版。得点価値の補正を含む） |
| `plus_sd`、`plus_q05`、`plus_q95` | 事後分布の標準偏差と 90% 区間 |
| `plus_pa` | 参考：打席数（上限つき）を固定効果に入れた版 |
| `plus_no_value` | 得点価値の補正を除いた値 |
| `plus_raw` | 縮小も環境の調整もしない値（実際の頻度 × 得点価値） |
| `raa` | リーグ平均に対する得点の増減（打席数を掛けた値） |

## 留意点

- **打席数を入れない版は、打席の少ない控えの打者をやや高く、レギュラーをやや低く見積もります。** 打席数を入れた版（`plus_pa`）はその逆で、故障明けの主力や昇格直後の若手を低く見積もります。
- **不確実性に含まれるのは一部です。** 打者の効果、相関で縮小し直したあと、補正係数、得点価値の補正の不確実性を含めています。打球単位のモデル、得点価値、相関行列は、推定した値を固定して使っているので、それらの不確実性は含まれません。
